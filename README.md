# 研伴：患者入组与随访 App

本项目是无业务服务器的 Expo React Native App。患者档案、历史登记记录、患者同意记录、随访任务和联系历史保存在设备的 SQLCipher 数据库中。旧版 AI 预筛和图片数据只为兼容历史记录保留，不再用于新患者登记。

- **简化日历设置**：优先识别和一键使用普通手机本地日历；生日、纪念日、倒计时及其他应用专用日历不再展示在常用列表。只有需要时才展开「更换日历（高级设置）」，技术账户名称不再直接暴露在日常界面。

- **保留既有逻辑**：一天至多一条正式随访日程、不包含患者姓名/数量；SQLCipher 数据、日历首页、两步入组、任务状态同步不变，尚未开启日历时仍保留旧原生闹钟。
- **限制与验证**：标准 Android `CalendarContract.Reminders.METHOD_ALERT` 仅请求日历提醒，无法直接修改厂商日历的独立响铃开关；日历通知权限、锁屏和免打扰设置仍由用户控制。需要真机验证实际响铃及事件兼容性。版本 `app.json=2.0.14`、npm `2.0.14-preview`、Android `versionCode=30` / `versionName=2.0.14-preview`；自动发布 `v2.0.14-preview.<run number>`。**升级请备份后覆盖安装，不要先卸载。**

### V2.0.13 相比 V2.0.12（2026-11-05）

- **新增系统日历提醒**：安卓在「我的 → 手机日历提醒」明确请求日历读写授权、展示本机可写日历供用户选择；选择后把未完成的随访计划日期同步成日历事件。默认上午 **09:00**，每个日期最多一条，标题为「研伴 · 今日随访提醒」、内容为「今天有随访任务，请打开研伴查看」，**不包含患者姓名、电话、诊断、任务数量**。
- **数据库仍为权威来源**：入组和随访状态更新通过现有 `refreshLocalReminders` 入口核对日历事件；已完成、取消和退出患者的任务不再计入未来提醒。日历事件 ID 和归属标记保存在应用私有设置中，用于去重、核查用户删除的事件并清理不需要的日程。过去日期不补建提醒，避免打开应用后意外补响。

- **设备限制和隐私**：日历账号可能同步到云端，因此界面明确提醒优先选择本地日历。日历应用的通知/锁屏/横幅/震动行为由系统和日历应用自行控制，不能保证所有厂商绝对准时。没有可写日历、权限被拒或同步失败时保留患者数据，允许重试。
- **不变内容**：沿用 V2.0.12 两步入组、患者同意、日历首页、随访任务与加密数据库；保留历史 AI 数据但不再调用 AI。

## 开发

需要 Node.js、npm，以及目标平台的原生工具链。

```powershell
npm install
npm run typecheck
npm start
```

## 安装到 Android

Windows 开发机需安装 Android Studio，并在 SDK Manager 中安装 Android SDK Platform 37、Build-Tools 37.0.0、Platform-Tools 和 NDK 27.1.12297006。设置 `ANDROID_HOME` 或 `mobile/android/local.properties` 的 `sdk.dir` 指向 Android SDK 目录。启动 Android 模拟器，或连接开启 USB 调试的 Android 设备，然后运行：

```powershell
npm run android
```

该命令会生成原生 Android 项目、编译并安装调试版 App。SQLCipher 必须通过原生构建启用，Expo Go 不适用于本 App。

## 安装到 iOS

iOS 原生构建需要 macOS 和 Xcode。当前 Windows 开发机无法本地编译或安装 iOS App。

## 首次使用

1. 安装并打开 App；按需要配置通知、闹钟和备份设置。
2. 在首页或「患者」页点击「新增或补录患者」，进入「入组患者信息登记」。
3. 填写姓名、电话、研究组别、入组日期；年龄、性别及大备注框可留空。
4. 在第二页确认患者是否同意。明确同意才生成患者档案及四个随访任务；不同意仅保存拒绝记录。
5. （安卓推荐）在「我的 → 手机日历提醒」授权并选择一个可写日历，研伴自动为有随访任务的日期创建一条不包含患者信息的系统日历提醒。请确认日历应用自身通知权限。

不再需要 AI API Key、心电图上传或 AI 预筛。界面中的同意选择不替代任何法定或研究方案要求的正式知情同意及临床资格核实程序。更新 App 直接覆盖安装，**不要先卸载**，否则本地患者数据和加密密钥可能丢失。

## 当前 MVP 边界

- 数据只保存在当前设备，不提供多设备同步、服务器备份或跨设备去重。
- 本机操作人和正式资格核实人由使用者填写；MVP 记录其确认和说明，但不具备账号身份验证或角色权限系统。
- Android 允许用户将随访计划同步到系统日历，由日历应用自行提醒；启用日历后停用本机正式 AlarmManager 每日闹钟，未启用日历时保留原生闹钟。Android 旧提醒链路由本机 AlarmManager 闹钟滚动调度；到点由原生接收器发通知并安排下一次，不要求 App 常驻后台。应用启动、设备开机、更新系统时间/时区或 App 升级时会恢复计划。建议授予通知与“闹钟和提醒”精确闹钟权限；强行停止、设备关机、撤销权限或厂商后台限制仍可能影响送达。
- Android 的患者随访、即时测试和 1 分钟延迟测试共用原生通知渠道与通知投递代码；延迟测试交给 AlarmManager。通知按闹钟类别发布，一加设备的长波形震动使用 `USAGE_ALARM`，由系统依照闹钟/免打扰规则处理；用户关闭渠道震动或启用完全静音时，系统仍可能屏蔽震动。「我的」页面提供统一配置入口，并在折叠区域显示状态、上次延迟测试结果和测试操作。
- Android 可由本机 Android SDK 构建；iOS 需要 Mac/Xcode 或后续配置的远程构建环境。
