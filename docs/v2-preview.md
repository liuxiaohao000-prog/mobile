# 研伴 V2.0 Preview — 变更、限制与验证

> 仅供内部验证。不要直接用于真实患者数据或临床生产流程；必须完成权限、提醒、恢复、隐私和真机回归测试。

## 已实施

- 采用统一青绿色医疗风格与任务优先的工作台。
- 「我的」页将诊断、AI 配置、备份和操作人设置收纳为折叠区域。
- 移除仅针对 OnePlus 的 `Handler.postDelayed` 震动补丁。
- Android 精确闹钟使用原生广播先发布高重要性提醒通知，再尝试执行五秒震动：
  - 使用 Alarm 用途的波形震动；最长约 5 秒。
  - 本次震动自动在约 5 秒后结束；停止不等于随访完成。
  - 不强行绕过静音、免打扰或通知渠道的震动设置。
  - 到点提醒的通知和震动不依赖常驻监测服务成功启动。
- 重启、时区更改、安装更新等恢复广播只重建计划，不再直接触发逾期提醒。
- 首次使用允许跳过外部备份目录授权；已有本地数据库不再因撤销备份目录授权而无法进入。若是重装恢复，应先选择原目录，再创建新档案。
- 升级 Android `versionCode` 到 20，应用 ID 保持 `com.local.patientfollowup`。

## 重要限制与未完成工作

1. Android 不保证强制停止后的闹钟仍可送达；各厂商对后台前台服务、DND 的约束存在差异。
2. 震动前台服务使用系统豁免类型，依赖 Android 对精确闹钟应用的资格判定；商店分发前需要做政策审核。
3. 仍使用现有的单一每日 09:00 原生闹钟及任务日期索引，尚未迁移到逐任务原生状态机。
4. **现有自动备份加密格式继承 MVP 的设备 ID + 内置秘密派生方式**。这并不构成高强度可迁移密钥保护；需要独立实现带版本迁移的用户恢复密钥方案，并核实旧备份可解密后再正式上线。
5. 仓库的 Release 构建目前仍使用仓库自带的 debug keystore（仅预览版）。这是公开仓库，不能视为安全的正式发布签名，后续应迁移到受保护的 Release keystore，并规划升级安装兼容性。
6. UI 和患者入组业务尚需全面回归，包括随访 1 / 3 / 6 / 12 日历月规则和新旧数据迁移。

## 真机验收

- 安卓 12–16 的一加/OPPO、小米、vivo、Pixel 或 Samsung 至少各选一台。
- 校验通知许可、精确闹钟许可、关闭通知震动、静音、免打扰、后台限制、恢复许可。
- 熄屏且 App 不在前台的 1 分钟测试与次日 09:00 正式提醒。
- 提醒停止后不可将对应随访任务误改成「已完成」；未完成任务次日继续提醒。
- 系统重启、时区变更、App 升级时不应在非计划时间发出意外提醒。
- 先升级原 APK 再检查原有数据库、图片附件和备份恢复，**不要通过卸载旧版测试升级**。

## 构建产物

GitHub Actions `Android APK` 会在 `v2/**` 分支构建、进行 TypeScript 检查，并在构建成功后上传 APK artifact 和发布预览版 GitHub prerelease。

构建通过不能代替真实设备测试。若需覆盖安装旧版，必须验证 APK 证书与旧版一致。正式版应使用单独保护的签名密钥。

## V2.0.4：低功耗常驻监测和通知设计

- 用户主动开启的 Android 原生 specialUse 前台服务；支持通知操作关闭监测，使用 START_STICKY 和 stopWithTask=false；不长时间持有 WakeLock。
- 在开机完成、升级完成事件下，若用户此前主动开启且系统仍允许通知，则尝试恢复常驻监测；系统限制启动时记录诊断错误。强行停止仍不可绕过。
- 每次应用进入前台时检查已启用的服务状态，并在用户可见的前台环境下尝试恢复，避免 Activity 未重建时漏恢复。
- 改为原生 RemoteViews 紧凑/展开通知：状态点、清晰的两级信息层次和三项数值卡片，支持日夜配色；包含待随访、今日完成和累计入组人数；轻点跳转工作台。
- 只在任务汇总变化时更新通知，应用不在前台时不轮询数据库或网络；跨天刷新允许系统延迟，统计并非持续实时刷新。
- 记录服务启动次数、上次启动时间、最近任务划掉时间及系统事件恢复尝试时间，用于问题诊断。

**仍需真机验证**：一加智能允许下的任务划掉、手机重启和系统内存清理；不同 Android 版本的自定义通知布局、深浅模式；短期与长期耗电。前台服务不能保证不会被 OEM 或系统终止，不能替代系统闹钟。

## V2.0.5：独立原生后台守护进程和直接精确闹钟投递

- 监测前台服务改为独立的 `:followup_guard` 轻量进程，不随 React Native UI 进程共同运行。独立进程不初始化 RN 运行时。
- 继续采用用户主动开启的 specialUse 前台服务。最近任务划除不能主动停止服务；系统强行停止应用包、资源紧张或厂商 UID 级清理仍可终止进程，无法承诺永不被杀。
- 监测快照由主进程通过显式服务 Intent 跨进程传递，避免跨进程 SharedPreferences 缓存导致显示过期；数据不含患者身份信息。
- 正式 9 点和一分钟测试改回 `setAlarmClock` 直接递送 `getForegroundService()`，原生提醒服务进入时记录测试时间戳；独立通知和约 5 秒震动。
- Android 13+ 允许用户在单独的「随访后台监测」通知渠道隐藏常驻通知，而不主动停止服务；正式随访提醒渠道保持独立。系统运行任务管理器的「停止应用」仍会终止后台运行。
- 恢复开机/升级后条件性恢复；不引入周期保活循环、持续网络、后台数据库轮询或长期 WakeLock。

验证重点：一加/OPPO 上在「智能允许」状态下划除最近任务后，检查守护进程是否继续存在、监测通知是否保留、系统闹钟是否成功投递以及五秒震动。仅编译通过不等于真机验证通过。

## V2.0.6：跨品牌的两级精确提醒投递

- 统一采用 Android 标准 AlarmManager API；没有任何品牌、型号或厂商私有权限判断。
- 准点：setAlarmClock -> PendingIntent.getForegroundService -> 原生提醒服务，独立于界面和守护服务。
- 备用：若准点通知未成功发布，90 秒后另一枚 setAlarmClock 通过独立 BroadcastReceiver 投递通知与最多五秒震动；成功投递后取消备用。
- 使用本机 SharedPreferences 记录正式提醒的日期、触发时间和通知成功时间，以及测试闹钟的主、备路径诊断。一次提醒只能发布一次，晚到的另一条路径不会重复震动。
- 正式随访在再次打开 App 时核对到点记录，若今日 9 点闹钟已过但通知未成功发布，在 9:00–21:00 期间尝试一次恢复通知，不补发已经过时的一分钟测试。
- 后台守护保留独立的 :followup_guard 原生前台服务和用户控制，且不通过高频 CPU/网络/JS 心跳实现保活。
- **限制**：如果 Android 或厂商将整个应用包置为 stopped / force-stop 状态，两枚系统 PendingIntent 仍可能同时取消。应用本身没有通用权限绕过用户或设备管理策略。守护通知是否显示也不是存活的充分证据。

验收要求：普通切后台、息屏、最近任务划除，每组连续至少 5 次；观察准点提醒与 90 秒备用提醒；检查是否有重复通知、重复震动；手机重启、权限撤销恢复和跨日提示；每日提醒不能遗漏新任务或产生无任务误报。必须分别在 Pixel/三星/一加 OPPO/小米 vivo 等厂商真机进行验证，CI 编译不代表真机通过。

## V2.0.7：修复 V2.0.5–2.0.6 普通后台提醒回归

用户在普通返回桌面时发现 V2.0.6 闹钟无法按时触发，进入应用后才迟到投递。这次不再增加定时器，直接恢复 V2.0.3–2.0.4 已在该设备验证过的单条原生广播投递路径：

- 正式随访和一分钟测试：`AlarmManager.setAlarmClock` → `PendingIntent.getBroadcast` → `FollowupReminderReceiver` → 先发布通知 → 原生一次性震动（最多 5 秒）。
- 移除 V2.0.6 的准点 `getForegroundService` 主入口和额外 90 秒的 `setAlarmClock`，避免两个系统闹钟及前台服务启动路径引入新的交互影响。
- 保留正式提醒本地日期去重与未送达日志；原生广播执行之后继续安排下一天闹钟，不依赖 React Native 页面存活。
- 保留用户可选的独立低功耗监测服务，仅负责可见的后台监测摘要，不作为消息发送前置条件。
- 本次为恢复基础可用性的回归修复，编译成功后仍须在普通退出、息屏、划掉最近任务的场景上实测。进程/包被系统强行停止时不能保证送达。


## V2.0.8：跨品牌的后台运行授权入口

背景：V2.0.7 用户真机三组一分钟提醒测试：
- 正常退出、亮屏：原生广播到达，较计划时间延迟 77 秒，但通知及震动执行。
- 正常退出、息屏：原生广播未及时送达，重新打开 App 可能触发延迟投递。
- 划掉最近任务：亮屏或息屏均不触发，重新进入 App 后也不补发一次性测试。
- 精确闹钟、通知、高重要性通知渠道和震动已开启；`PowerManager.isIgnoringBatteryOptimizations` 为 false；`ActivityManager.isBackgroundRestricted` 为 false。前者不是故障的唯一证明，后者也不是厂商后台策略全开的证明。

本版不再更换 `setAlarmClock` 投递入口和保活策略。新增标准 Android 的用户主动授权入口：
- 声明 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（仅为了发起由用户决定的系统豁免授权），原生 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 包含 `package:` URI；系统不支持该页面时回退到电池优化列表或研伴应用信息页。
- 设置页在「随访提醒」下面增加清晰可见的「后台运行授权」，根据电池优化豁免状态展示操作。用户点击并二次确认后才打开系统授权页，不自动申请。
- 增加标准 Android `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS` 和 `ACTION_APPLICATION_DETAILS_SETTINGS` 跳转；不指定任何厂商组件，也不修改其他应用设置。
- 诊断增加自身 `UsageStatsManager.appStandbyBucket`，并修正“通知、精确闹钟均允许即可完全可靠”的误导状态。系统界面返回后重新读取所有授权状态。
- 不绕过明确的「强行停止」。不保證所有 OEM 对设置批准后有一致的后台调度行为，不以系统豁免取代基于 AlarmManager 的本地原生提醒。
- 该权限仅应在提醒为核心且 Doze/App Standby 确实严重影响投递的使用场景下申请；若将来通过 Google Play 分发，应重新审核政策允许的直接豁免用途和用户告知。


## V2.0.9：启动今日随访速览与点击拨号

- App 本地 SQLCipher 数据库初始化完成后，立即显示紧凑的「今日随访速览」模态弹窗；包含今日到期与已逾期的未完成随访，使用与工作台一致的业务状态。
- 只列出仍处于 ACTIVE 的患者，排除已完成、已取消、已退出患者，并将同一患者多条到期任务合并展示。
- 对每位患者显示姓名、患者编号、随访节点、是否今日到期或逾期及联系电话。号码可点击打开系统 `tel:` 拨号界面，仅预填号码，**不会自动呼叫**；无需 CALL_PHONE 危险权限。可点击「查看任务」打开对应随访详情。
- 弹窗支持关闭，右上角新增「今日随访」手动入口供随时重开；冷启动自动显示；从后台返回超过两分钟时再次显示，但从手机拨号盘返回时不会立即打断。
- 所有患者隐私信息仅在前台 App 内展示和读取，不写入系统常驻通知或独立守护服务，不联网，无新数据库字段或迁移。
- 本版只改今日随访展示和导航，不改变 V2.0.8 已存在的 AlarmManager、通知、震动、电池优化设置和独立后台守护链路。
- 测试重点：无到期任务/单人/多人含逾期/同一人多项任务/已完成/患者退出/空电话；打开系统拨号盘、返回应用、按钮重开；冷启动及跨应用长时间切换。
